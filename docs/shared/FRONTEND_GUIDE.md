# Ridely 백엔드 연동 가이드

프론트엔드 개발에 필요한 내용을 모았다. 각 API의 요청·응답 상세는 **Swagger 문서**를 확인하면 된다.

---

## 1. 시작하기

### 서버 실행

```bash
docker compose up -d                                   # DB 기동 (PostgreSQL + PostGIS)
./mvnw spring-boot:run -Dspring-boot.run.profiles=local # 서버 기동
```

`.env` 파일이 필요하다. `.env.example`을 복사해 값을 채운다(키는 백엔드 담당에게 요청).

### API 문서

| 주소 | 내용 |
|---|---|
| http://localhost:8080/swagger-ui.html | API 목록·요청·응답·직접 호출 |
| http://localhost:8080/v3/api-docs | 기계가 읽는 명세(JSON) — 클라이언트 코드 생성에 사용 가능 |

Swagger 화면 우측 상단 **Authorize** 버튼에 로그인으로 받은 `accessToken`을 넣으면
인증이 필요한 API도 화면에서 바로 호출해볼 수 있다.

### 서버 주소

| 환경 | 주소 |
|---|---|
| PC 브라우저 | `http://localhost:8080` |
| 안드로이드 에뮬레이터 | `http://10.0.2.2:8080` |

에뮬레이터는 자기 자신을 `localhost`로 보기 때문에 호스트 PC를 `10.0.2.2`로 부른다.

모든 API 경로는 `/api/v1`로 시작한다.

## 2. 응답 형식

**모든 응답이 같은 형태로 감싸여 있다.**

성공:
```json
{
  "success": true,
  "data": { "userId": 1, "loginId": "rider" },
  "error": null
}
```

실패:
```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "AUTH-201",
    "message": "인증 정보가 올바르지 않습니다",
    "details": null
  }
}
```

입력값 검증 실패 시 `details`에 항목별 사유가 담긴다:
```json
{
  "success": false,
  "error": {
    "code": "COMMON-001",
    "message": "잘못된 요청입니다",
    "details": {
      "nickname": "닉네임은 2~50자여야 합니다",
      "email": "이메일 형식이 올바르지 않습니다"
    }
  }
}
```

- 성공 여부는 HTTP 상태 코드와 `success` 중 어느 쪽으로 판단해도 된다
- `error.message`는 **사용자에게 그대로 보여줘도 되는 문구**로 작성돼 있다
- 값이 없는 필드는 응답에서 아예 빠진다(`null`로 오지 않음)

### 값 형식

| 항목 | 형식 | 예 |
|---|---|---|
| 시간 | ISO 8601 (UTC) | `2026-08-02T09:03:32.240107Z` |
| 좌표 | 소수 | `lat: 37.5434`, `lng: 126.8997` |
| 거리 | 미터(정수) | `distanceM: 407` |

## 3. 인증

### 흐름

```
로그인 → accessToken(15분) + refreshToken(14일) 저장
   ↓
모든 요청 헤더에 Authorization: Bearer {accessToken}
   ↓
AUTH-301(만료) 응답 → /auth/refresh 로 새 토큰 발급 → 원 요청 재시도
   ↓
AUTH-302 또는 COMMON-002 → 저장된 토큰 삭제 → 로그인 화면
```

### 401 응답 구분이 중요하다

같은 401이라도 코드에 따라 대응이 다르다.

| 코드 | 의미 | 대응 |
|---|---|---|
| `AUTH-301` | 액세스 토큰 만료 | **재발급 후 재시도** |
| `AUTH-302` | 리프레시 토큰 만료·위조·이미 사용됨 | 재로그인 |
| `COMMON-002` | 토큰 없음·형식 오류 | 재로그인 |

`AUTH-302`인데 재발급을 반복하면 무한 루프에 빠진다.

### ⚠️ 재발급 시 주의

**사용한 리프레시 토큰은 즉시 폐기된다.** 재발급 응답으로 받은 새 토큰 쌍으로
반드시 교체해야 하며, 이전 토큰을 다시 보내면 `AUTH-302`가 온다.

여러 요청이 동시에 401을 받아 재발급을 각각 호출하면, 먼저 성공한 하나를 빼고
나머지는 실패한다. **재발급 요청을 하나로 모으는 처리**(진행 중이면 그 결과를 기다림)를
넣어두는 것이 안전하다.

액세스 토큰 수명이 15분이라 재발급이 자주 일어난다. 한 시간에 네 번꼴이고, 라이딩 중에는
화면이 계속 열려 있어 그때마다 요청이 겹칠 수 있다. 위 처리를 넣지 않으면 드물게 나던
`AUTH-302`가 눈에 띄게 늘어난다.

### 만료 시간은 응답에서 읽는다

`accessTokenExpiresIn`(초)이 로그인·재발급 응답에 함께 온다. **15분을 코드에 적어두지 말고
이 값을 쓴다.** 서버가 수명을 줄이면 하드코딩한 쪽은 만료된 토큰으로 계속 호출하게 된다.

### 토큰 저장

`localStorage`에 저장한다(기획 확정 사항).

```
ridely.auth.access_token
ridely.auth.refresh_token
```

### 로그아웃

`POST /auth/logout`에 리프레시 토큰을 보낸다. 이미 폐기된 토큰이어도 204를 반환하므로,
**응답과 무관하게 저장된 토큰을 지우면 된다.**

## 4. 에러 코드

현재 정의된 전체 목록이다. 새 API가 추가되면 코드도 늘어난다.

| 코드 | HTTP | 의미 | 주로 발생하는 곳 |
|---|---|---|---|
| `COMMON-001` | 400 | 입력값 검증 실패 | 모든 요청 (details 참고) |
| `COMMON-002` | 401 | 로그인 필요 | 토큰 없이 보호 API 호출 |
| `COMMON-003` | 403 | 남의 리소스 접근 | 저장 경로·라이딩 세션 |
| `COMMON-004` | 404 | 대상 없음 | 조회 실패, **없는 경로** |
| `COMMON-006` | 405 | 메서드 불일치 | `details.allowed`에 받는 메서드가 온다 |
| `COMMON-007` | 415 | Content-Type 불일치 | `details.supported`에 받는 형식이 온다 |
| `COMMON-500` | 500 | 서버 오류 | 예기치 못한 실패 |
| `AUTH-101` | 409 | 이미 가입된 아이디 | 회원가입 |
| `AUTH-102` | 400 | 비밀번호 정책 위반 | 회원가입, **비밀번호 변경** |
| `AUTH-201` | 401 | 아이디 또는 비밀번호 불일치 | 로그인, **비밀번호 변경·탈퇴의 본인 확인** |
| `AUTH-202` | 401 | 정지된 계정 | 로그인 |
| `AUTH-301` | 401 | 액세스 토큰 만료 | 인증 필요한 모든 API |
| `AUTH-302` | 401 | 리프레시 토큰 무효 | 토큰 재발급 |
| `ROUTE-001` | 400 | 우선순위 합이 1이 아님 | 코스 추천, 사용자 설정 |
| `ROUTE-002` | 400 | 목표 거리가 적절하지 않음 | 코스 추천 |
| `ROUTE-003` | 400 | 서비스 지역 밖 | 코스 추천, **인프라 POI 조회** |
| `ROUTE-006` | 422 | 주변에 후보가 없음 | 코스 추천 |
| `SAVED-001` | 409 | 이미 저장한 코스 | 코스 저장 |
| `POI-001` | 404 | 반경 내 결과 없음 | 주변 관광지 조회 |
| `GEO-001` | 502 | 외부 검색 서비스 실패 | 장소 검색 |

`AUTH-201`은 **아이디가 없는 경우와 비밀번호가 틀린 경우를 구분하지 않는다.**
구분하면 가입된 아이디가 노출되기 때문이며, 화면에서도 "아이디 또는 비밀번호를
확인해 주세요"처럼 합쳐서 안내해야 한다.

`ROUTE-006`은 `ROUTE-003`과 다르다. **003은 서비스 지역 밖이고 006은 지역 안인데
주변에 관광지·급수대·수리소·대여소가 하나도 없는 경우다.** 서비스 지역이 사각형이라
한강에서 먼 모서리에 그런 구역이 남아 있다.

**사용자가 고칠 수 있으므로 안내도 그렇게 해야 한다.** 출발지를 한강 쪽으로 옮기거나
도착지를 지정하면 대개 해결된다 - 도착지가 있으면 후보를 찾는 범위가 출발지 주변이
아니라 두 점을 잇는 선 주변이 되기 때문이다. 주로 도착지 없는 순환 코스에서 난다.

⚠️ **`POI-001`은 관광지 조회에서만 난다.** 인프라 POI(`/pois/nearby`)와 장소 검색은
결과가 0건이어도 200에 빈 배열을 준다. 세 API의 규칙이 다르니 한 번에 처리하지 말 것.

| API | 0건일 때 |
|---|---|
| `/tours/nearby` | `POI-001` (404) |
| `/pois/nearby` | 200 + 빈 배열 |
| `/geo/search` | 200 + 빈 배열 |

## 5. 사용 가능한 API

### 인증 (토큰 불필요)

| Method | 경로 | 설명 |
|---|---|---|
| POST | `/api/v1/auth/signup` | 회원가입 |
| POST | `/api/v1/auth/login` | 로그인 (토큰 발급) |
| POST | `/api/v1/auth/refresh` | 토큰 재발급 |
| POST | `/api/v1/auth/logout` | 로그아웃 (204) |

비밀번호 정책: **8~30자, 영문·숫자·특수문자 각 1자 이상**

### 회원 (토큰 필요)

| Method | 경로 | 설명 |
|---|---|---|
| GET | `/api/v1/users/me` | 내 정보 조회 |
| PATCH | `/api/v1/users/me` | 내 정보 수정 (닉네임·이메일) |
| PATCH | `/api/v1/users/me/password` | 비밀번호 변경 |
| DELETE | `/api/v1/users/me` | 회원 탈퇴 |

수정은 **보낸 항목만** 변경된다. `{"nickname": "새닉네임"}`만 보내면 이메일은 유지된다.

#### 비밀번호 변경

```json
PATCH /api/v1/users/me/password
{ "currentPassword": "현재비번", "newPassword": "새비번" }
```

성공하면 204, 본문은 없다.

⚠️ **성공 뒤 저장된 토큰을 지우고 로그인 화면으로 보낸다.** 리프레시 토큰이 전부
폐기되므로 재발급이 안 된다. 요청을 보낸 기기도 마찬가지다. 쓰던 액세스 토큰은
만료될 때까지 남지만 그 뒤로는 쓸 수 없다.

새 비밀번호 정책은 회원가입과 같다 — 8~30자, 영문·숫자·특수문자 각 1자 이상.
현재 비밀번호와 같은 값을 보내도 통과한다.

| 상황 | 코드 |
|---|---|
| 현재 비밀번호 불일치 | `AUTH-201` |
| 새 비밀번호 정책 위반 | `AUTH-102` |
| 빈값 | `COMMON-001` |

#### 회원 탈퇴

```json
DELETE /api/v1/users/me
{ "password": "현재비번" }
```

성공하면 204, 본문은 없다. **되돌릴 수 없다.**

⚠️ **본문에 비밀번호를 담아 보낸다.** DELETE에 본문을 싣는 것이라 HTTP 클라이언트에
따라 기본 설정에서 본문을 빼고 보낼 수 있다. 비밀번호가 맞는데 `COMMON-001`이 온다면
이쪽을 먼저 확인한다.

성공 뒤 저장된 토큰을 모두 지우고 로그인 화면으로 보낸다.

화면은 확인 단계를 두 번 두는 것이 관례다 — 무엇이 사라지는지 안내한 뒤 비밀번호를 받는다.

- **함께 사라지는 것**: 설정, 저장한 코스, 라이딩 기록과 궤적, 로그인 세션
- **남는 것**: 추천받았던 코스. 회원과의 연결만 끊기고 코스 번호로는 계속 조회된다

탈퇴한 아이디로 다시 가입할 수 있다.

| 상황 | 코드 |
|---|---|
| 비밀번호 불일치 | `AUTH-201` |
| 빈값·본문 누락 | `COMMON-001` |

### 관광지 (토큰 불필요)

| Method | 경로 | 설명 |
|---|---|---|
| GET | `/api/v1/tours/nearby` | 주변 관광지 조회 |
| GET | `/api/v1/tours/{tourAttractionId}` | 관광지 상세 조회 |

```
GET /api/v1/tours/nearby?lat=37.5434&lng=126.8997&radiusM=2000&contentTypeIds=12
```

| 파라미터 | 필수 | 설명 |
|---|---|---|
| `lat`, `lng` | ✅ | 중심 좌표 |
| `radiusM` | | 반경(m). 기본 1000, 최대 5000 |
| `contentTypeIds` | | `12`=관광지, `14`=문화시설, `39`=음식점. CSV. 미지정 시 전체 |

응답에 조회 조건(`center`, `radiusM`)이 함께 담기므로 지도 중심·반경 원을 다시 그릴 때
요청값을 따로 보관하지 않아도 된다. 결과는 **가까운 순**이며 각 항목에 `distanceM`이 있다.

현재 적재 범위는 **한강 서울 구간**(아라한강갑문~잠실)이다. 그 밖의 지역은 `POI-001`이 온다.
지도 초기 위치를 한강 근처로 두면 확인하기 좋다. (예: 선유도공원 `37.5434, 126.8997`)

#### 상세 조회

```
GET /api/v1/tours/12
```

**추천 응답의 `waypoints` 중 `type`이 `TOUR_ATTRACTION`인 항목의 `id`를 그대로 넣는다.** 목록 조회가 주는 `tourAttractionId`도 같은 값이다.

```json
{
  "tourAttractionId": 12,
  "contentId": "2781792",
  "contentTypeId": "12",
  "title": "선유도공원",
  "lat": 37.5434, "lng": 126.8997,
  "addr1": "서울특별시 영등포구 선유로 343",
  "tel": "02-2631-9368",
  "firstImageUrl": "https://tong.visitkorea.or.kr/cms/resource/92/2781792_image2_1.jpg",
  "thumbnailUrl": "https://tong.visitkorea.or.kr/cms/resource/92/2781792_image3_1.jpg",
  "overview": "한강 위의 정수장을 재생한 생태공원이다."
}
```

⚠️ **사진·주소·전화·개요가 없는 콘텐츠가 많다.** 원본에 값이 없으면 **필드 자체가 응답에서 빠지므로**(2장의 `non_null` 규칙) `=== null` 비교는 실패한다. 필드 유무로 판단할 것.

⚠️ **`distanceM`은 담기지 않는다.** 기준점 없이 한 건을 읽는 것이라 거리가 성립하지 않는다. 거리가 필요하면 `/tours/nearby`를 쓴다.

이미지 주소는 **서버가 `https`로 바꿔서 내보낸다.** TourAPI 원본은 `http://tong.visitkorea.or.kr/...`인데 앱이 https에서 뜨므로 그대로면 혼합 콘텐츠로 막힌다. 그래서 받은 값을 손댈 필요가 없다. 다만 `index.html`의 CSP `img-src`에 `https://tong.visitkorea.or.kr`을 넣어야 표시된다.

| 에러 | 뜻 |
|---|---|
| `COMMON-004` (404) | 없는 번호. 반경 문제인 `POI-001`과 다르다 — 요청을 고쳐도 같은 결과다 |

### 인프라 POI (토큰 불필요)

| Method | 경로 | 설명 |
|---|---|---|
| GET | `/api/v1/pois/nearby` | 주변 자전거 인프라 조회 |

```
GET /api/v1/pois/nearby?lat=37.5265&lng=126.9339&radiusM=1000&types=WATER,BIKE_STATION
```

| 파라미터 | 필수 | 설명 |
|---|---|---|
| `lat`, `lng` | ✅ | 지도 중심 좌표 |
| `radiusM` | | 반경(m). 기본 1000, 최대 5000 |
| `types` | | CSV. 미지정 시 전체 |

종류는 일곱이고 `items[].type`으로 구분된다. `WATER`·`TOILET`·`CERT_CENTER`·`AIR_PUMP`는 응답에서 모두 `type: "ROUTE_FACILITY"`이고 `facilityType`이 세부 종류를 담는다.

결과는 **종류에 상관없이 하나의 목록에 거리순으로 합쳐** 내려간다. 레이어별로 나눠 그릴 거면 `type`으로 묶으면 된다.

#### 0건이 정상 상태다

⚠️ **반경 안에 아무것도 없어도 200에 빈 배열이 온다.** 관광지 조회가 `POI-001`(404)을 내는 것과 다르다. **에러 분기를 태우면 안 된다.**

종류마다 적재 밀도가 크게 달라서다.

| 종류 | 적재 건수 | 반경 1km에서 0건이 나오는 비율 |
|---|---|---|
| `BIKE_STATION` 따릉이 | 3,239 | 16.8% |
| `AIR_PUMP` 공기주입기 | 1,163 | |
| `TOILET` 화장실 | 688 | |
| `WATER` 급수대 | 185 | 84.4% |
| `ACCIDENT_ZONE` 사고다발지 | 111 | |
| `CERT_CENTER` 인증센터 | 88 | |
| `REPAIR_SHOP` 수리소 | 24 | 93.8% |

**수리소·급수대 레이어는 기본 반경으로 켜면 화면이 거의 빈다.** 실측으로 여의도한강공원에서 수리소가 1,000m에 0건, 5,000m에 5건이었다. 희소한 종류는 반경을 크게 잡거나, 반경 대신 「가장 가까운 곳」을 안내하는 편이 낫다.

#### 서비스 지역 밖은 다르다

중심 좌표가 한강 서울 구간 밖이면 **`ROUTE-003`(400)**이 온다. 0건과 구분해야 한다 - 0건은 지도를 조금 옮기면 되지만 지역 밖은 얼마를 움직여도 안 나온다.

#### 전체 조회 — 내 위치를 서버에 안 보내고 주변 시설 보기

| Method | 경로 | 설명 |
|---|---|---|
| GET | `/api/v1/pois/all` | 적재된 인프라 **전부** (토큰 불필요) |

```
GET /api/v1/pois/all
```

**파라미터가 없다.** 이 API는 「내 근처」를 서버에 묻지 않으려고 만든 것이다. 앱이 이 응답을 **한 번 받아 폰에 저장**해 두고, **GPS와의 거리를 폰 안에서 계산해** 반경 안의 시설만 보여준다. 요청에 위치가 없으니 서버는 사용자가 어디 있는지 알 수 없다(`LOCATION_PRIVACY_ARCHITECTURE.md`).

⚠️ **요청에 좌표·반경·격자·「내 근처」 같은 값을 절대 붙이지 않는다.** 서버가 무시하더라도 요청 자체에 위치가 실려 나가면 원칙이 깨진다. 한강 서울 구간 밖에 적재된 것이 있어도 다 내려오니, 지역으로 거르는 것도 폰에서 한다.

```json
{
  "success": true,
  "data": {
    "items": [
      {"type": "ROUTE_FACILITY", "id": 5, "name": "여의도 급수대", "lat": 37.526, "lng": 126.933, "facilityType": "WATER"},
      {"type": "BIKE_STATION", "id": 2, "name": "여의나루역 대여소", "lat": 37.527, "lng": 126.934}
    ],
    "totalCount": 5498
  }
}
```

- **종류**는 `/pois/nearby`와 같고 `type`·`facilityType`으로 구분한다. 종류 순서(시설 → 수리소 → 따릉이 → 사고다발지)와 종류 안의 번호순이 항상 같다
- **응답이 슬림하다.** `distanceM`이 없고(기준점이 없다), 사고다발지 **폴리곤이 없다**, 따릉이는 이름·좌표만 온다. 도형이 필요하면 반경 조회나 코스 추천 응답의 통과 구역을 쓴다. 필드는 종류별로 고정돼 있다 — 사고다발지는 `dangerLevel`·`occurrenceCount`·`deathCount`, 수리소는 `addr`·`tel`·`isFree`·`operatingHours`
- **캐시**: `Cache-Control: max-age=3600`과 ETag(약한 형태 `W/"..."`)를 준다. 저장해 둔 것이 있으면 `If-None-Match`로 다시 물어라 — 바뀐 게 없으면 본문 없이 **304**다. 적재 직후엔 최대 1시간 옛 목록이 보일 수 있다
- **크기**: 실데이터 약 4,500건 기준 원본 약 525KB, **gzip 전송 약 108KB**다. `fetch`는 압축 해제를 알아서 하니 따로 할 일은 없다
- **낡음의 상한**: 이 API는 요청 제한이 없는 공개 API라 **서버도 결과를 5분 메모리에 둔다**(`ridely.poi.all-cache-seconds`). 적재가 바뀐 뒤 최대 5분(서버) + 1시간(HTTP 캐시)까지 옛 목록이 나갈 수 있고, 앱이 폰에 저장해 둔 사본은 그와 별개로 24시간 쓴다
- 결과가 없어도 200에 빈 배열이다
- ⚠️ **모든 사용자가 항상 전부 받는 구조**라 적재가 늘면 다운로드가 그만큼 커진다(약 5,500건). 저장은 `localStorage`로 시작하되 몇 배로 늘면 `IndexedDB`로 옮겨야 한다. 커지면 서버 로그에 경고가 남는다
- 관광지는 이 응답에 없다(개요가 길어 무겁다). `/tours/nearby`를 쓴다

### 장소 검색 (토큰 불필요)

| Method | 경로 | 설명 |
|---|---|---|
| GET | `/api/v1/geo/search` | 장소명·주소 → 좌표 |

```
GET /api/v1/geo/search?query=여의도한강공원
```

결과에서 하나를 고르면 `lat`·`lng`를 그대로 코스 추천 요청의 출발지·도착지에 실으면 된다. 최대 10건이 온다.

```json
{
  "placeName": "여의도한강공원",
  "address": "서울 영등포구 여의도동 85",
  "lat": 37.52638860108943,
  "lng": 126.93512931714196,
  "inServiceArea": true
}
```

⚠️ **서비스 지역 밖도 결과에 나온다.** 목록에서 빼지 않고 `inServiceArea: false`로 표시한다. 조용히 사라지면 사용자가 검색어를 잘못 썼다고 생각하고 계속 다시 치기 때문이다. **화면이 이 값으로 선택 불가 처리를 하고 이유를 보여 줘야 한다.**

`address`는 도로명 주소이고, 없으면 지번이 들어온다. 공원·한강 둔치는 건물이 없어 도로명이 비는 경우가 흔하다.

**결과가 없으면 200에 빈 배열이다.** 오타나 없는 장소를 친 것은 실패가 아니다. 외부 검색 서비스가 응답하지 못했을 때만 **`GEO-001`(502)**이 온다 - 다시 쳐야 하는 상황과 잠시 뒤 재시도해야 하는 상황이 갈린다.

### 코스 추천

| Method | 경로 | 설명 |
|---|---|---|
| POST | `/api/v1/routes/recommend` | AI 코스 설계. 비회원도 호출 가능 |
| GET | `/api/v1/routes/{recommendedRouteId}` | 추천 결과 재조회 |

요청·응답 필드가 많아 여기 옮기지 않는다. **Swagger가 정본**이고 설계 의도·에러코드는 `ridely_api_spec.md` 5장에 있다. 화면을 붙이기 전에 아래를 확인하면 된다.

- 응답은 **평면 구조**다. `summary`·`ai` 중첩이 없고 `aiTitle`·`aiCoachComment`처럼 접두사가 붙는다. 경로 형상은 `routeGeoJson` **문자열**이라 `JSON.parse`가 필요하다.
- `avoidDangerZonesApplied: true`여도 `passingDangerZones`는 비지 않는다. 주의 등급은 그대로 지나가기 때문이다. **"안전 경로" 표시를 붙이면 안 된다.**

#### `Idempotency-Key` — 재시도가 AI를 두 번 부르지 않게

`POST /routes/recommend`는 응답에 10초 안팎이 걸리고 그 한 번이 LLM을 두 번 부른다. 모바일에서 전파가 끊겨 재시도하면 서버는 그것이 재시도인지 새 요청인지 모른다. 그래서 화면이 알려 준다.

**요청마다 새 UUID를 만들고, 재시도할 때만 같은 값을 다시 보낸다.**

```js
// 요청을 만들 때 한 번
const key = crypto.randomUUID();

// 이 요청의 재시도는 전부 같은 key를 쓴다
fetch('/api/v1/routes/recommend', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', 'Idempotency-Key': key },
  body: JSON.stringify(request),
});
```

20분 안에 같은 키가 오면 새 코스를 만들지 않고 첫 응답을 그대로 돌려준다. 헤더가 없어도 동작하며 그때는 매번 새로 만든다.

⚠️ **다시 추천받기 버튼은 새 UUID를 만들어야 한다.** 같은 값을 보내면 방금 본 코스가 다시 온다. 요청 조건이 아니라 키로만 판정하므로 출발지·거리를 그대로 둔 채 눌러도 새 키면 새 코스가 나온다.

**저장되지 않는 응답이 있다.** 요청대로 처리되지 않은 것을 재시도로 다시 받느니 새로 시도하는 편이 낫기 때문이다. 화면이 따로 할 일은 없고, **재시도가 빠르지 않다고 해서 고장은 아니라는 뜻**이다.

| 응답 | 재시도하면 |
|---|---|
| `aiProvider: "FALLBACK"` | 새로 만든다. LLM이 성공할 기회를 다시 준다 |
| 회피를 켰는데 `avoidDangerZonesApplied: false` | 새로 만든다. 경유지 조합이 매번 달라 다음에 될 수 있다 |
| 실패(4xx·5xx) | 새로 만든다. 실패는 저장하지 않는다 |

⚠️ **키를 잘못 재사용하면 마지막 요청이 이긴다.** 같은 키에 다른 본문을 보내면 서버는 새 코스를 만들고 저장값을 그것으로 덮어쓴다. 에러를 내지 않으므로 **화면이 키를 요청 하나에 묶어 관리하지 않으면 조용히 어긋난다.**

#### `aiProvider` — AI 해설인지 규칙 응답인지

`ai`로 시작하는 필드를 무엇이 만들었는지 알린다. 대체가 아니면 사용 중인 LLM 공급자 이름이 오고 지금은 `gemini`다.

⚠️ **`=== 'gemini'`로 분기하지 말 것.** 공급자는 서버 설정이라 바뀔 수 있다. **`=== 'FALLBACK'`인지만 보면 된다.**

**`FALLBACK`이면 LLM이 아니라 규칙이 만든 것이다.** 호출 실패·타임아웃·LLM이 고른 경유지가 실재하지 않음·톤 위반 가운데 하나가 났고, 서버가 코스를 포기하는 대신 측정값으로 응답을 조립했다.

```
"aiCoachComment": "총 11.8km, 예상 53분 코스예요. 운동 강도는 MODERATE 수준이에요."
"aiTitle": "11.8km 라이딩 코스"
```

| 화면 | 대체 아님 | `FALLBACK` |
|---|---|---|
| 코치 말풍선 | AI 코치로 표시 | **AI 코치로 표시하면 안 된다.** 측정값 나열이라 코치의 말로 보이지 않는다 |
| 경유지 선정 이유 | `waypoints[].reason`에 문장이 온다 | **항상 비어 있다** |
| 코스 자체 | 정상 | **정상이다.** 코스를 감추라는 뜻이 아니다 |

`reason`은 대체가 아닐 때도 비어 있을 수 있다. LLM이 특정 경유지의 이유를 안 쓰는 경우가 있어 **어느 쪽이든 null 처리는 필요하다.**

`GET /routes/{id}`에도 실린다. 저장한 코스를 다시 열 때도 같은 판단이 필요하다.

#### 사고다발지 표시의 근거는 `passingDangerZones`

⚠️ **지도에 이 배열을 그리고, `aiDangerZoneAlert`는 곁들이는 문장으로만 써야 한다.**

배열은 DB 값 그대로라 지점명·등급·건수·좌표가 정확하다. 반면 문장은 **LLM이 자유롭게 쓴 것**이고 온도가 0이 아니라 매번 달라진다. **서버는 이 문장의 내용을 검사하지 않는다.**

라이더에게 위치를 알리는 자리가 둘이고 **둘 다 화면이 만든다.** LLM을 거치지 않는다.

| 시점 | 화면이 할 일 | 재료 |
|---|---|---|
| 코스 확인 | 지도에 구역을 표시 | `passingDangerZones[].polygonGeoJson`·`lat`·`lng` |
| 라이딩 중 | 근접 알림 (B2 담당) | 같은 배열 + 기기 GPS |

근접 알림 거리는 서버 설정 `ridely.route.danger-zone-alert-distance-m`에 200m로 잡혀 있다. **판정은 화면이 한다** - 서버가 알림을 보내지 않는다.

**문장만 보여 주면 이 둘이 비고 위치 전달이 전부 LLM에 걸린다.** 자전거 사고다발지 정보라 오차의 대가가 크다.

### 사용자 설정

| Method | 경로 | 설명 |
|---|---|---|
| GET | `/api/v1/users/me/settings` | 설정 조회. 회원 전용 |
| PATCH | `/api/v1/users/me/settings` | 부분 수정. 보낸 필드만 바뀐다 |

```json
{
  "avoidDangerZones": false,
  "defaultPriorityConvenience": 0.50,
  "defaultPriorityExercise":    0.30,
  "defaultPriorityScenery":     0.20,
  "units": "km",
  "vibrationEnabled": true,
  "notificationEnabled": true
}
```

- **우선순위 셋은 묶음이다.** 하나만 보내면 나머지가 기존 값으로 남아 합이 1을 벗어난다. 셋 중 하나라도 바꾸려면 셋 다 보내야 하고 합은 **정확히 1.00**이어야 한다. 위반은 `ROUTE-001`.
- `units`는 서버가 저장만 한다. **응답 거리는 항상 km**이므로 mile 표시는 화면에서 변환한다.
- 사고다발지 회피 토글은 회원이면 이 API로, 비회원이면 `X-Ridely-Avoid-Danger-Zones` 헤더로 보낸다. **회원이 헤더를 함께 보내면 무시된다.**

### 저장 경로 (토큰 필요)

| Method | 경로 | 설명 |
|---|---|---|
| POST | `/api/v1/saved-routes` | 추천 코스를 내 목록에 담기 |
| GET | `/api/v1/saved-routes` | 내 저장 목록 (페이지) |
| GET | `/api/v1/saved-routes/{savedRouteId}` | 단건 조회 |
| PATCH | `/api/v1/saved-routes/{savedRouteId}` | 이름·메모·즐겨찾기 수정 |
| DELETE | `/api/v1/saved-routes/{savedRouteId}` | 저장 취소 (204) |

```
GET /api/v1/saved-routes?page=0&size=20&favoriteOnly=true&sort=name
```

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| `page` | 0 | 0부터 시작 |
| `size` | 20 | 최대 100 |
| `favoriteOnly` | | `true`면 즐겨찾기만 |
| `sort` | `latest` | `latest`(저장 역순) 또는 `name` |

목록·단건·저장·수정이 **모두 같은 형태**를 돌려준다. 목록은 이것이 `content[]`에 담기고 `page`·`size`·`totalElements`·`totalPages`가 함께 온다.

```json
{
  "savedRouteId": 3,
  "recommendedRouteId": 42,
  "customName": "주말 한강 코스",
  "memo": "선유도공원 카페 들르기 좋음",
  "isFavorite": true,
  "createdAt": "2026-08-28T14:20:00+09:00",
  "aiTitle": "한강 따라 14km, 적당히 땀 빼는 코스",
  "totalDistanceKm": 14.8,
  "estimatedDurationMin": 58,
  "intensityLevel": "MODERATE"
}
```

- **경로 좌표가 없다.** 지도를 그릴 때는 `recommendedRouteId`로 `GET /routes/{id}`를 따로 부른다. 좌표를 넣으면 목록 한 페이지가 수천 개를 실어 나른다.
- **`customName`은 null일 수 있다.** 이름을 안 붙인 경우이고, 그때는 `aiTitle`을 대신 보여 준다. `sort=name`도 같은 기준으로 정렬한다.
- **저장할 때 `isFavorite`을 함께 보낼 수 있다.** 저장 다이얼로그에 체크박스를 뒀다면 `PATCH`를 이어 부르지 않아도 된다.
- **메모를 지우려면 빈 문자열을 보낸다.** `PATCH`에서 `null`은 "안 보냈다"라는 뜻이라 지우기와 구분되지 않는다.
- 같은 코스를 두 번 저장하면 `SAVED-001`(409)이다. 저장 버튼의 상태를 눌린 모양으로 바꿔 두면 대부분 막을 수 있다.

### 라이딩 세션 (토큰 필요)

| Method | 경로 | 설명 |
|---|---|---|
| POST | `/api/v1/riding-sessions` | 라이딩 시작 |
| PATCH | `/api/v1/riding-sessions/{ridingSessionId}` | 라이딩 종료 |
| GET | `/api/v1/riding-sessions` | 내 라이딩 기록 (페이지) |
| GET | `/api/v1/riding-sessions/summary` | 누적 통계 |
| GET | `/api/v1/riding-sessions/{ridingSessionId}` | 기록 단건. **궤적은 여기서만 온다** |

시작할 때는 추천 코스 번호만 보낸다. 비우면 자유 주행이고, 그때는 본문을 통째로 생략해도 된다.

```json
{ "recommendedRouteId": 42 }
```

종료할 때 라이딩 중 모은 값을 한 번에 보낸다. 매초 보내지 않는 이유는 배터리와 통신량 때문이다.

```json
{
  "distanceKm": 14.6,
  "avgSpeedKmh": 16.2,
  "isCompleted": true,
  "visitedPoiCount": 2,
  "alertReceivedCount": 1,
  "trackGeoJson": "{\"type\":\"LineString\",\"coordinates\":[[126.89,37.54],[126.90,37.54]]}"
}
```

- **시작·종료 시각은 서버가 찍는다.** 보내지 마라. 기기 시계가 앞서 있으면 시작보다 이른 종료 시각이 들어가 종료가 막힌다.
- **종료 요청은 재시도해도 안전하다.** 이미 끝난 세션에 다시 보내면 에러 대신 기존 기록이 그대로 돌아온다. 타임아웃 후 그냥 다시 보내면 된다. 단 **값이 달라도 덮어쓰지 않으므로**, 수정 목적으로 다시 보내지는 마라.
- **`trackGeoJson`은 솎아서 보낸다.** 10초 또는 50m 간격이 기준이다. 매 좌표를 다 보내면 요청이 너무 커진다. 고도가 섞여 있어도 서버가 떨군다. GeoJSON LineString이 아니면 `COMMON-001`이다.
- **궤적은 단건 조회에서만 온다.** 목록에 넣으면 한 페이지가 수 MB가 된다. 기록 상세 화면은 `GET /riding-sessions/{id}`를 부른다. 트랙을 안 보내고 종료한 세션이면 단건에서도 null이고, 좌표는 2차원이다(고도는 서버가 떨군다).
- **`endedAt`이 null이면 달리는 중이다.** 앱이 죽었다 살아났을 때 목록에서 이 항목을 찾아 이어 달리면 된다. 진행 중인 세션이 있어도 새 라이딩 시작은 막지 않는다.

#### 누적 통계

마이페이지(#9)와 저장 경로(#8)의 통계 카드에 쓴다.

```json
GET /api/v1/riding-sessions/summary

{
  "totalRideCount": 8,
  "totalDistanceKm": 112.4,
  "avgSpeedKmh": 15.8,
  "lightCount": 2,
  "moderateCount": 5,
  "hardCount": 1,
  "challengeCount": 0
}
```

**목록과 따로 부른다.** 목록은 한 페이지를, 통계는 전체를 센다. 저장 경로 화면처럼 둘 다 필요하면 **두 요청을 병렬로 보내면 된다.**

- **종료된 라이딩만 센다.** 달리는 중인 세션(`endedAt`이 null)은 거리·속도가 아직 없어 평균을 끌어내린다.
- ⚠️ **네 단계의 합이 `totalRideCount`보다 작을 수 있다.** 강도는 추천 코스가 가진 값이라 자유 주행에는 없다. **차이가 자유 주행 횟수다** — 「추천 없이 달린 N회」로 보여 줄 수 있다.
- **`avgSpeedKmh`는 아예 오지 않을 수 있다.** 기록이 없거나 속도를 보내지 않고 종료한 경우다(2장의 「값이 없는 필드는 빠진다」). 0으로 채우지 않은 것은 시속 0km로 달린 것처럼 보이기 때문이다. `=== null`이 아니라 필드 유무로 판단하고 `-`로 표시한다.
- **기록이 없어도 200이다.** 가입 직후가 그 상태이고 값은 전부 0이다. 에러 분기를 만들지 않아도 된다.
- ⚠️ **`totalDistanceKm`의 소수 자리가 일정하지 않다.** 기록이 없으면 `0`, 있으면 `12.50`처럼 둘째 자리까지 온다(DB 컬럼이 소수 둘째 자리라 합계도 따라간다). 값으로는 같지만 **그대로 찍으면 「12.50km」로 보인다.** 표시할 자리수는 화면에서 정한다.

## 6. 아직 없는 API

화면 개발 순서를 잡을 때 참고한다. 준비되는 대로 이 문서와 Swagger에 반영된다.

- **홈의 인프라 요약 카드** (반경 1km, 종류별 개수만). 지금은 `/pois/nearby`로 받아 화면에서 세면 된다. 개수만 필요한데 종류당 최대 100건이 오므로, 홈 진입이 무거우면 알려 달라.
- **홈의 코치 코멘트 위젯.** 같은 성격의 문장이 추천 응답의 `aiNextStepSuggestion`에 있지만 홈에서는 추천을 부르지 않는다. 전용 API를 만들면 홈 진입마다 LLM 호출이 붙어 느려지므로, 당분간 정적 문구를 권한다.

### 없는 것으로 확인된 것

**코스 입력 화면의 세부 옵션 체크박스** (자전거 전용도로 우선 / 음수대·수리소·관광지 경유)는 **API에 없다.** 우선순위 3축(`priorityConvenience`·`priorityExercise`·`priorityScenery`)으로 통합됐다 — 편의 축이 음수대·수리소를, 풍경 축이 관광지를 대신한다. 체크박스를 만들면 보낼 곳이 없다.

## 8. 막힐 때

| 증상 | 확인할 것 |
|---|---|
| 연결 자체가 안 됨 | 서버·DB가 떠 있는지, 에뮬레이터면 주소가 `10.0.2.2`인지 |
| 모든 요청이 401 | 헤더 형식이 `Authorization: Bearer {토큰}`인지 (`Bearer` 뒤 공백 한 칸) |
| 401이 반복됨 | 코드가 `AUTH-301`인지 `AUTH-302`인지 (3장 참고) |
| **404 `COMMON-004`** | **경로 오타. 끝에 슬래시가 붙지 않았는지도 본다** |
| **405 `COMMON-006`** | **`error.details.allowed`에 이 경로가 받는 메서드가 들어 있다** |
| **415 `COMMON-007`** | **`Content-Type: application/json`을 붙였는지** |
| `POI-001`만 나옴 | 좌표가 한강 구간인지 (적재 범위 밖은 결과가 없다) |
| 500이 나옴 | 백엔드 담당에게 요청 시각과 호출 내용을 알려주면 서버 로그로 원인 확인 가능 |

**404·405·415는 요청을 고치면 되는 것이고 서버 장애가 아니다.** 예전에는 이 셋이 전부 500으로 나가 구분할 수 없었다.
