# Ridely 백엔드 연동 가이드

프론트엔드 개발에 필요한 내용을 모았다. 각 API의 요청·응답 상세는 **Swagger 문서**를 확인하면 된다.

---

## 1. 시작하기

### 서버 실행

```bash
docker compose up -d                                   # DB 기동 (PostgreSQL + PostGIS)
./mvnw spring-boot:run -Dspring-boot.run.profiles=local # 서버 기동
```

`.env` 파일이 필요하다. `.env.example`을 복사해 값을 채운다(키는 백엔드 담당에게 요청).

### API 문서

| 주소 | 내용 |
|---|---|
| http://localhost:8080/swagger-ui.html | API 목록·요청·응답·직접 호출 |
| http://localhost:8080/v3/api-docs | 기계가 읽는 명세(JSON) — 클라이언트 코드 생성에 사용 가능 |

Swagger 화면 우측 상단 **Authorize** 버튼에 로그인으로 받은 `accessToken`을 넣으면
인증이 필요한 API도 화면에서 바로 호출해볼 수 있다.

### 서버 주소

| 환경 | 주소 |
|---|---|
| PC 브라우저 | `http://localhost:8080` |
| 안드로이드 에뮬레이터 | `http://10.0.2.2:8080` |

에뮬레이터는 자기 자신을 `localhost`로 보기 때문에 호스트 PC를 `10.0.2.2`로 부른다.

모든 API 경로는 `/api/v1`로 시작한다.

## 2. 응답 형식

**모든 응답이 같은 형태로 감싸여 있다.**

성공:
```json
{
  "success": true,
  "data": { "userId": 1, "loginId": "rider" },
  "error": null
}
```

실패:
```json
{
  "success": false,
  "data": null,
  "error": {
    "code": "AUTH-201",
    "message": "인증 정보가 올바르지 않습니다",
    "details": null
  }
}
```

입력값 검증 실패 시 `details`에 항목별 사유가 담긴다:
```json
{
  "success": false,
  "error": {
    "code": "COMMON-001",
    "message": "잘못된 요청입니다",
    "details": {
      "nickname": "닉네임은 2~50자여야 합니다",
      "email": "이메일 형식이 올바르지 않습니다"
    }
  }
}
```

- 성공 여부는 HTTP 상태 코드와 `success` 중 어느 쪽으로 판단해도 된다
- `error.message`는 **사용자에게 그대로 보여줘도 되는 문구**로 작성돼 있다
- 값이 없는 필드는 응답에서 아예 빠진다(`null`로 오지 않음)

### 값 형식

| 항목 | 형식 | 예 |
|---|---|---|
| 시간 | ISO 8601 (UTC) | `2026-08-02T09:03:32.240107Z` |
| 좌표 | 소수 | `lat: 37.5434`, `lng: 126.8997` |
| 거리 | 미터(정수) | `distanceM: 407` |

## 3. 인증

### 흐름

```
로그인 → accessToken(1시간) + refreshToken(14일) 저장
   ↓
모든 요청 헤더에 Authorization: Bearer {accessToken}
   ↓
AUTH-301(만료) 응답 → /auth/refresh 로 새 토큰 발급 → 원 요청 재시도
   ↓
AUTH-302 또는 COMMON-002 → 저장된 토큰 삭제 → 로그인 화면
```

### 401 응답 구분이 중요하다

같은 401이라도 코드에 따라 대응이 다르다.

| 코드 | 의미 | 대응 |
|---|---|---|
| `AUTH-301` | 액세스 토큰 만료 | **재발급 후 재시도** |
| `AUTH-302` | 리프레시 토큰 만료·위조·이미 사용됨 | 재로그인 |
| `COMMON-002` | 토큰 없음·형식 오류 | 재로그인 |

`AUTH-302`인데 재발급을 반복하면 무한 루프에 빠진다.

### ⚠️ 재발급 시 주의

**사용한 리프레시 토큰은 즉시 폐기된다.** 재발급 응답으로 받은 새 토큰 쌍으로
반드시 교체해야 하며, 이전 토큰을 다시 보내면 `AUTH-302`가 온다.

여러 요청이 동시에 401을 받아 재발급을 각각 호출하면, 먼저 성공한 하나를 빼고
나머지는 실패한다. **재발급 요청을 하나로 모으는 처리**(진행 중이면 그 결과를 기다림)를
넣어두는 것이 안전하다.

### 토큰 저장

`localStorage`에 저장한다(기획 확정 사항).

```
ridely.auth.access_token
ridely.auth.refresh_token
```

### 로그아웃

`POST /auth/logout`에 리프레시 토큰을 보낸다. 이미 폐기된 토큰이어도 204를 반환하므로,
**응답과 무관하게 저장된 토큰을 지우면 된다.**

## 4. 에러 코드

현재 정의된 전체 목록이다. 새 API가 추가되면 코드도 늘어난다.

| 코드 | HTTP | 의미 | 주로 발생하는 곳 |
|---|---|---|---|
| `COMMON-001` | 400 | 입력값 검증 실패 | 모든 요청 (details 참고) |
| `COMMON-002` | 401 | 로그인 필요 | 토큰 없이 보호 API 호출 |
| `COMMON-004` | 404 | 대상 없음 | 조회 실패 |
| `COMMON-500` | 500 | 서버 오류 | 예기치 못한 실패 |
| `AUTH-101` | 409 | 이미 가입된 아이디 | 회원가입 |
| `AUTH-102` | 400 | 비밀번호 정책 위반 | 회원가입 |
| `AUTH-201` | 401 | 아이디 또는 비밀번호 불일치 | 로그인 |
| `AUTH-202` | 401 | 사용할 수 없는 계정(탈퇴·정지) | 로그인 |
| `AUTH-301` | 401 | 액세스 토큰 만료 | 인증 필요한 모든 API |
| `AUTH-302` | 401 | 리프레시 토큰 무효 | 토큰 재발급 |
| `POI-001` | 404 | 반경 내 결과 없음 | 주변 관광지 조회 |

`AUTH-201`은 **아이디가 없는 경우와 비밀번호가 틀린 경우를 구분하지 않는다.**
구분하면 가입된 아이디가 노출되기 때문이며, 화면에서도 "아이디 또는 비밀번호를
확인해 주세요"처럼 합쳐서 안내해야 한다.

## 5. 사용 가능한 API

### 인증 (토큰 불필요)

| Method | 경로 | 설명 |
|---|---|---|
| POST | `/api/v1/auth/signup` | 회원가입 |
| POST | `/api/v1/auth/login` | 로그인 (토큰 발급) |
| POST | `/api/v1/auth/refresh` | 토큰 재발급 |
| POST | `/api/v1/auth/logout` | 로그아웃 (204) |

비밀번호 정책: **8~30자, 영문·숫자·특수문자 각 1자 이상**

### 회원 (토큰 필요)

| Method | 경로 | 설명 |
|---|---|---|
| GET | `/api/v1/users/me` | 내 정보 조회 |
| PATCH | `/api/v1/users/me` | 내 정보 수정 (닉네임·이메일) |

수정은 **보낸 항목만** 변경된다. `{"nickname": "새닉네임"}`만 보내면 이메일은 유지된다.

### 관광지 (토큰 불필요)

| Method | 경로 | 설명 |
|---|---|---|
| GET | `/api/v1/tours/nearby` | 주변 관광지 조회 |

```
GET /api/v1/tours/nearby?lat=37.5434&lng=126.8997&radiusM=2000&contentTypeIds=12
```

| 파라미터 | 필수 | 설명 |
|---|---|---|
| `lat`, `lng` | ✅ | 중심 좌표 |
| `radiusM` | | 반경(m). 기본 1000, 최대 5000 |
| `contentTypeIds` | | `12`=관광지, `14`=문화시설, `39`=음식점. CSV. 미지정 시 전체 |

응답에 조회 조건(`center`, `radiusM`)이 함께 담기므로 지도 중심·반경 원을 다시 그릴 때
요청값을 따로 보관하지 않아도 된다. 결과는 **가까운 순**이며 각 항목에 `distanceM`이 있다.

현재 적재 범위는 **한강 서울 구간**(아라한강갑문~잠실)이다. 그 밖의 지역은 `POI-001`이 온다.
지도 초기 위치를 한강 근처로 두면 확인하기 좋다. (예: 선유도공원 `37.5434, 126.8997`)

### 기타

| Method | 경로 | 설명 |
|---|---|---|
| GET | `/api/v1/health` | 서버 상태 확인 |

## 6. 아직 없는 API

화면 개발 순서를 잡을 때 참고한다. 준비되는 대로 이 문서와 Swagger에 반영된다.

- 코스 추천 (`POST /routes/recommend`) — AI 코스 설계, 가장 핵심
- 저장 경로 (`/saved-routes`)
- 라이딩 세션 (`/riding-sessions`)
- 사용자 설정 (`/users/me/settings`) — 사고다발지 회피 토글, 기본 우선순위
- 인프라 POI (`/pois/nearby`) — 음수대·수리소·따릉이·사고다발지
- 지오코딩 (`/geo/search`) — 주소·장소명 → 좌표
- 회원 탈퇴, 비밀번호 변경

## 7. CORS

로컬 개발 환경에서 아래 주소를 허용해 두었다.

```
http://localhost:8080
http://10.0.2.2:8080      (안드로이드 에뮬레이터)
http://localhost:8100     (Cordova 개발 서버)
file://                   (Cordova 빌드 후 WebView)
```

다른 포트를 쓰면 백엔드 담당에게 알려주면 추가한다.

## 8. 막힐 때

| 증상 | 확인할 것 |
|---|---|
| 연결 자체가 안 됨 | 서버·DB가 떠 있는지, 에뮬레이터면 주소가 `10.0.2.2`인지 |
| 모든 요청이 401 | 헤더 형식이 `Authorization: Bearer {토큰}`인지 (`Bearer` 뒤 공백 한 칸) |
| 401이 반복됨 | 코드가 `AUTH-301`인지 `AUTH-302`인지 (3장 참고) |
| `POI-001`만 나옴 | 좌표가 한강 구간인지 (적재 범위 밖은 결과가 없다) |
| 500이 나옴 | 백엔드 담당에게 요청 시각과 호출 내용을 알려주면 서버 로그로 원인 확인 가능 |
