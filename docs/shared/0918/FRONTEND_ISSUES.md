# 프론트엔드 이슈 기록 — 발견 및 해결 (2026-09-18)

Cordova 프론트엔드(`android-shell/`) 코드 리뷰 및 실사용 흐름 시뮬레이션에서 발견한 문제들이다. 팀원 리뷰로 발견된 것, 전체 코드 재검토로 발견된 것, 실사용 흐름을 순서대로 따라가며 시뮬레이션해서 발견한 것 세 갈래로 찾았다.

## 해결됨

### 1. 로그인 상태에서 코스 추천 화면의 사고다발지 회피 체크박스가 무시됨

**파일**: `www/js/pages/route-plan.js`

**증상**: 로그인 상태에서 회피 체크박스를 켜도, 마이페이지 설정이 꺼져 있으면 회피가 적용 안 됨 (반대도 마찬가지).

**원인**: 백엔드는 회원이면 `X-Ridely-Avoid-Danger-Zones` 헤더를 무시하고 마이페이지 설정값만 쓴다(`RouteController.java` 주석 참고). 헤더는 비회원 전용인데 화면은 로그인 여부와 무관하게 항상 체크박스 값을 헤더로 보냈다.

**조치**: 로그인 상태면 체크박스를 마이페이지 설정값으로 채우고 잠그며, 헤더 자체를 안 보낸다. 힌트 문구("로그인 상태에서는 마이페이지 설정을 따라요")를 추가했다.

### 2. `res.json()`이 JSON이 아닌 응답에서 원문 에러를 그대로 노출

**파일**: `www/js/api.js`

**증상**: 백엔드가 죽어있거나 앞단이 502를 HTML로 내려주면 `SyntaxError`가 그대로 화면에 `Unexpected token '<' ...` 형태로 찍힘.

**조치**: `parseJsonSafely()` 헬퍼로 감싸서 파싱 실패 시 `ApiError('COMMON-500', '서버와 통신하지 못했어요', ...)`로 변환. `apiFetch`·`rawRefresh` 양쪽에 적용.

### 3. 배포 주소 변경 시 놓치기 쉬운 3곳이 문서화 안 돼 있었음

**파일**: `www/js/api.js:6`

**조치**: `API_BASE` 주석에 같이 바꿔야 하는 3곳(API_BASE 자신, `index.html`의 CSP `connect-src`, EC2의 `CORS_ALLOWED_ORIGINS`)을 정리해뒀다.

### 4. 코스 추천 화면 재진입 시 이전 출발지/도착지가 몰래 재사용됨

**파일**: `www/js/pages/route-plan.js`

**증상**: `state.selectedStart`/`selectedEnd`가 코스 추천 한 번 받은 뒤에도 리셋 안 됨. 화면엔 "선택됨" 배지가 안 보이는데(새로 그려진 HTML이라 기본 숨김) 실제로는 재검색 없이 이전 좌표로 제출됨 — 화면에 보이는 것과 실제로 쓰이는 값이 어긋나는 문제.

**조치**: `render()` 진입 시 두 값을 `null`로 리셋.

### 5. 카카오맵 로드가 한 번 실패하면 세션 내내 영구 고장

**파일**: `www/js/map.js`

**증상**: `loadPromise`가 실패해도 캐시에 그대로 남아서, 세션 중 카카오 SDK 로드가 한 번이라도 실패하면(네트워크 순간 끊김 등) 그 뒤 어떤 화면에서 지도를 열어도 캐시된 실패가 즉시 재거부됨. 원인이 사라져도 앱 재시작 전까지 복구 불가.

**조치**: `script.onerror`에서 `loadPromise = null`로 초기화 후 reject — 다음 시도가 새로 로드해볼 수 있게.

### 6. 홈 화면 지도 로딩 중 다른 탭으로 이동하면 콘솔 에러

**파일**: `www/js/pages/home.js`

**증상**: `searchInfra`가 지연 콜백(카카오 SDK 첫 로딩 완료 후) 안에서 DOM을 다시 조회하는데, 그 사이 사용자가 다른 탭으로 넘어가면 `#infra-summary-body`가 이미 없어서 `null.textContent = ...`로 에러.

**조치**: `summaryEl`이 없으면 조기 반환.

### 7. 로그인/회원가입 버튼에 연타 방지가 없었음

**파일**: `www/js/pages/auth.js`

**증상**: 연타 시 특히 회원가입에서 동시에 두 요청이 나가 하나는 성공, 하나는 `AUTH-101`(이미 가입됨) — 실제로는 성공했는데 에러 문구가 같이 뜨는 혼란.

**조치**: route-plan.js와 같은 패턴으로 제출 버튼 잠금 추가.

### 8. 라이딩 종료 API 실패 시 GPS 추적이 이미 멈춰있던 문제

**파일**: `www/js/pages/riding.js`

**증상**: `endRiding()`이 API 호출 **전에** `stopTracking()`부터 호출. 종료 요청이 실패해서(연결 끊김 등) 사용자가 재시도하는 동안 실제로는 계속 이동해도 그 구간 GPS가 기록 안 됨.

**조치**: 종료 API가 **성공한 뒤에만** `stopTracking()`을 호출하도록 순서 변경. 실패 시 추적을 계속 살려두고, 재시도 시점의 최신 `distanceM`/`track`으로 다시 계산해서 보낸다.

### 9. `riding.js` — "자유 주행으로 시작"을 눌러도 이전에 고른 저장 코스의 사고다발지가 안 지워짐

**증상**: 저장한 코스 하나를 선택(`selectSavedRoute`)했다가 마음 바꿔서 "자유 주행으로 시작"을 클릭하면, `state.lastRecommend`는 `null`로 지우지만 지도에 그리고 근접 판정에 쓰는 `dangerZones` 클로저 변수는 그대로 남아있었다. 자유 주행인데 방금 선택했다가 취소한(지금은 무관한) 코스의 사고다발지 폴리곤이 지도에 그려지고 근접 알림도 그 기준으로 계속 떴다.

**조치**: "자유 주행으로 시작" 클릭 핸들러에서 `dangerZones = []`도 같이 리셋.

### 10. `riding.js` — 알림 영역(`#riding-alert`)을 4곳이 공유해서 안전 경고가 다른 메시지에 덮여씀

**증상**: `alertEl.innerHTML`을 쓰는 곳이 이어서 추적 안내(`resumeInterruptedSession`)·사고다발지 근접 경고(`checkDangerZones`)·GPS 에러(`onPositionError`)·종료 실패 메시지(`endRiding`) 네 군데인데 전부 같은 자리를 덮어썼다. 사고다발지 경고가 뜬 직후 GPS 오차 메시지 하나만 떠도 안전 경고가 화면에서 사라졌다.

**조치**: 사고다발지 근접 경고 전용 슬롯(`#riding-danger-alert`)을 새로 분리. `checkDangerZones()`는 이제 이 슬롯에만 쓰고, 이어서 추적 안내·GPS 에러·종료 실패는 기존 `#riding-alert`를 그대로 쓴다 — 서로 덮어쓸 일이 없다. 라이딩 시작 시 두 슬롯 다 초기화.

### 11. `route-plan.js` — 타임아웃 후 재시도가 Idempotency-Key 재사용 규칙을 안 지킴

**증상**: `docs/shared/FRONTEND_GUIDE.md`의 규칙 — "요청이 실패해서 재시도할 때만 같은 키를 재사용해야 한다"(목적: 타임아웃돼서 재클릭했는데 서버는 이미 처리 중/완료였을 경우 LLM 중복 호출 방지) — 를 지키지 않고, `submit()`이 호출될 때마다 매번 `newIdempotencyKey()`로 새 키를 만들었다. "실패해서 재시도"와 "새로 추천받기"를 구분하지 않아서, 이 메커니즘이 막으려던 상황이 그대로 뚫려있었다.

**조치**: 직전 실패 시도의 `{key, bodyJson}` 스냅샷을 기억해뒀다가, 이번 제출 내용(body)이 그것과 **완전히 같으면** 같은 키를 재사용하고, 다르면(입력을 바꿨거나 첫 시도) 새 키를 생성. 성공하면 스냅샷을 지워서 다음 클릭은 완전히 새 요청으로 취급한다. (같은 키에 다른 body를 보내면 서버가 저장값을 덮어쓴다는 가이드 경고 때문에, 단순히 "직전 실패면 무조건 재사용"이 아니라 body까지 비교한다.)

### 12. 위치정보(GPS) 서버 무전송 전환

**배경**: 위치정보법상 개인위치정보 수집·보관 리스크를 원천 차단하기 위해, 기기 GPS로 얻은 정보(원본이든 거리·속도 같은 가공값이든)를 서버로 절대 전송하지 않도록 구조를 바꿨다. 상세 원칙과 기능별 변경표는 `docs/shared/0918/LOCATION_PRIVACY_ARCHITECTURE.md` 참고.

**변경 파일**:
- `www/js/pages/route-plan.js`, `www/pages/route-plan.html` — GPS "현재 위치" 버튼 제거, 출발/도착 모두 장소 검색으로만 선택
- `www/js/ride-storage.js` (신규) — 라이딩 세션을 localStorage에 저장/조회/집계하는 모듈
- `www/js/pages/riding.js` — `POST/PATCH /riding-sessions` 호출 제거, 세션 생성·저장을 전부 로컬로 전환
- `www/js/pages/riding-history.js` — 서버 조회 대신 로컬 기록 표시
- `www/js/pages/mypage.js` — 서버 요약 API 대신 로컬 집계로 누적 통계 계산
- `www/pages/auth.html`, `www/js/pages/auth.js` — 회원가입 시 위치정보 수집·이용 동의 체크박스 추가(서버 전송 없음, 클라이언트 고지용)

**트레이드오프**: 라이딩 기록이 기기 로컬에만 남음 — 앱 삭제·기기 변경 시 소실, 기기 간 동기화 불가. "현재 위치에서 출발" 편의 기능 없어짐.

## 미해결 — 우선순위 낮음 (코드 리뷰로 발견, 아직 손 안 댐)

### 9. `auth.js`(유틸)의 `logout()`이 불필요한 동적 import 사용

`www/js/auth.js` — 이미 파일 최상단에서 `token-store.js`를 정적으로 import하고 있는데, `logout()` 함수 안에서 `getRefreshToken`만 따로 동적 import함. 기능상 문제는 없으나 정적 import에 합치는 게 맞다.

### 10. `state.js`의 `pendingAfterLogin` 필드가 죽은 코드

`www/js/state.js` — 선언만 되고 어디서도 안 씀. 실제 "로그인 후 원래 화면으로 복귀"는 URL 쿼리파라미터(`?return=`)로 처리된다. 제거하거나 실제로 연결해야 함.

### 11. `riding.js` — 세션 재개(`resumeInterruptedSession`)와 사용자의 수동 시작이 겹치는 좁은 레이스 컨디션

앱이 죽었다 재실행되면서 로컬에 저장된 세션을 이어받는 로직이 코스 정보를 다시 불러오는 동안(비동기), 그 틈에 사용자가 "라이딩 시작"을 누르면 추적 루프(`watchPosition`/`setInterval`)가 두 개 동시에 돌 수 있음. 재현하려면 타이밍이 꽤 정확해야 해서 실제 발생 가능성은 낮음.

### 12. `api.js`의 `fetch()` 호출 자체가 try/catch로 안 감싸져 있음

`doFetch()`·`rawRefresh()` 안의 `fetch()` 호출(JSON 파싱 이전 단계)이 실패하면(진짜 네트워크 단절 등) `ApiError`가 아니라 원본 `TypeError`가 그대로 던져짐. 2번 항목과 같은 계열인데 한 층 더 앞에서 놓친 부분.
