# 스파이크 — 두루누비 API로 자전거길 형상을 대체할 수 있는가

> 대상: `national_bike_route` 데이터 소스 | 타임박스 **반나절** | 상태: **❌ 기각 (2026-08-11)**
> 관련: `SCHEMA_CHANGE_ROUTE_GEOM.md`(기각으로 유효 유지), `DATA_SOURCES.md` #11
>
> **결론: 두루누비는 자전거 코스를 제공하지 않는다.** 코스 144건이 전부 걷기(DNWW)다.
> 행안부 CSV + 거리 임계값 3km 방식을 그대로 간다. 상세는 6장.

---

## 1. 왜 하는가

행안부 자전거길 DB(CSV)에는 **구간 경계가 없다.** 노선별로 좌표를 순서대로 나열할 뿐,
끊어진 자리나 갈래가 바뀌는 지점을 표시하지 않는다.

그래서 우리는 "좌표 간격이 3km를 넘으면 구간이 바뀐 것"이라는 **자체 규칙**을 만들어야 했다.
근거는 확보했지만(간격 중앙값 25m, p99.9 675m, 2.57↔4.55km 사이 공백) 어디까지나 추정이다.

한국관광공사 **두루누비 정보 서비스**는 코스별 **GPX 파일**을 준다.
GPX는 `<trkseg>`로 **구간 경계를 원본에 명시한다.**

**채택되면 자체 규칙이 통째로 사라진다.** 그것이 이 스파이크의 전부다.

## 2. 곁다리로 얻는 것

| 필드 | 쓰임 |
|---|---|
| `crsDstnc` | 공식 코스 거리 → `total_length_km` 논쟁 종결 |
| `crsIdx` | 노선을 몇 조각으로 나눌지 = 공식이 이미 나눠서 준다 |
| `crsLevel`(1/2/3), `crsTotlRqrmHour` | W3 파이프라인의 강도 라벨 산출 재료 |
| `crsTourInfo`·`crsSummary`·`crsContents` | LLM 프롬프트 재료, W5 RAG 임베딩 소스 |
| `sigun`, `crsCycle` | 지역 매핑·순환형 판별 |

서비스ID가 `Durunubi`, 엔드포인트가 `B551011` — **한국관광공사 TourAPI 계열이다.**
공모전이 TourAPI 활용을 필수로 걸고 있으므로 활용 데이터에 TourAPI 서비스가 하나 더 붙는다.

## 3. 실행 절차

```bash
docker compose up -d
./mvnw spring-boot:run -Dspring-boot.run.profiles=local
```

### 0단계 — 파서 먼저 (API 호출 없음)

```bash
./mvnw test -Dtest=GpxParserTest
```

개발계정 한도(일 1,000건)를 파서 디버깅에 쓰지 않기 위해 먼저 돌린다.

### 1단계 — 키가 통하는가

```bash
curl 'localhost:8080/api/v1/poc/durunubi/raw?op=routeList&numOfRows=5'
```

`COMMON-500`이면 **서버 로그에 포털 오류 원문이 찍힌다.**
`SERVICE_KEY_IS_NOT_REGISTERED_ERROR`면 두루누비 활용신청이 아직 반영되지 않은 것이다
(자동승인이지만 포털↔관광공사 동기화에 약 30분).

### 2단계 — 커버리지 ★ 중단 게이트

```bash
curl 'localhost:8080/api/v1/poc/durunubi/coverage' | jq
```

`matchedCount`가 **0이면 여기서 중단한다.** 3단계로 넘어가지 않는다.

단, 자동 매칭을 그대로 믿지 말 것. 두루누비가 "한강종주자전거길"을 "한강 자전거길"처럼
다르게 부를 수 있어 토큰 매칭이 빗나갈 수 있다. **`allThemeNames`를 눈으로 훑어본 뒤** 판단한다.

### 3단계 — GPX 형상

```bash
# MVP 구간부터 (한강종주). 빠르게 감을 잡는다
curl 'localhost:8080/api/v1/poc/durunubi/geometry?routeCode=2' | jq

# 매칭된 전체
curl 'localhost:8080/api/v1/poc/durunubi/geometry' | jq
```

## 4. 판정 기준

핵심 지표는 하나다 — **`gpxTrksegTotal`이 `csvPartsAt3km`와 맞는가.**

| 결과 | 뜻 | 조치 |
|---|---|---|
| 구간 수 대체로 일치 | 휴리스틱이 원본과 같은 답을 냈다 | **채택.** GPX를 정본으로. CSV·임계값·`SCHEMA_CHANGE_ROUTE_GEOM` 폐기 |
| trkseg가 전부 1 | GPX도 구간 정보가 없다 | **부분 채택 검토.** 형상은 CSV 유지, `crsDstnc`·`crsLevel`·텍스트만 차용 |
| 크게 어긋남 | 두 소스가 다른 형상을 담는다 | **연장 금지.** MVP 구간(아라·한강종주)만 보고 판단 |
| 커버리지 0 | 지자체 코스 전용 | **기각.** 기존안(MultiLineString + 3km + 공식 거리)으로 복귀 |

## 5. 채택 시 따라오는 비용

`route_facility`(주변시설 CSV)는 행안부 노선코드 1~13 기준이고 `national_bike_route_id` FK로 묶여 있다.
두루누비 **코스 단위로 갈아타면 이 FK 매핑이 깨진다.** 좌표 기반 최근접 매칭으로 바꾸거나
두 소스를 별도 테이블로 병존시켜야 한다. 공짜 전환이 아니다.

폐기 대상이 되는 미커밋 코드: `BikeRouteCsvReader`, `BikeRouteIngestService(Impl)`,
`NationalBikeRouteDao`, `BikeRouteIngestTest`, `SeedFileProperties`(노선 좌표 부분).

### 실측 과정에서 드러난 것

| 호출 | 결과 |
|---|---|
| `routeList` (필터 없음) | COMMON-500 — **원인 미확정**(DB 미기동 시점과 겹쳐 재확인 필요). 판정에는 영향 없음 |
| `routeList&brdDiv=DNWW` | **0건** — 길 목록 오퍼레이션이 사실상 비어 있다 |
| `routeList&brdDiv=DNBW` | 0건 |
| `courseList&brdDiv=DNBW` | 144건, 그러나 **반환 항목은 전부 `brdDiv:"DNWW"`** |
| `courseList` (필터 없음) | 144건, 전부 DNWW |

**`brdDiv` 필터는 동작하지 않는다.** DNBW를 요청해도 걷기 코스가 돌아온다.
서버 필터를 믿고 판정했다면 "144건 조회 성공"으로 오독할 뻔했다.
응답의 `brdDiv` 값을 직접 집계해서야 0건임이 드러났다.

코스 내용은 전부 코리아둘레길 계열이다 — 남파랑길·서해랑길.

### 매뉴얼과 실제가 다른 이유 — ✅ 확인됨 (2026-08-14)

활용매뉴얼 v4.1(2024-03)의 응답 예시는 `crsKorNm: "밀양강 자전거길"`, `brdDiv: DNBW`,
`totalCount: 740`이다. 현재는 144건에 자전거 0건이다.
**자전거 데이터가 서비스에서 빠진 것으로 보인다.** 매뉴얼이 갱신되지 않았을 뿐이다.

> 교훈: 매뉴얼의 응답 예시는 데이터 존재의 근거가 아니다.
> 다음에 새 공공 API를 검토할 때는 명세를 읽기 전에 실호출로 건수부터 센다.

**추정이 맞았다.** 개선요청 회신(한국관광공사 대외개방운영팀, 2026-08-14)으로 확인됐다.

> 두루누비 사이트에 **자전거길 서비스가 종료**되었다는 공지가 있어 우선 전달드립니다. 매뉴얼에 자전거길 관련 정보는 종료되어 사용하지 않는다고 문서 갱신하여 업로드하겠습니다. 조치예정일시 26년 8월중.

두루누비 공지 `notice_idx=10123` 제목이 **「두루누비 일반길 / 자전거길 서비스 종료 안내」**다.

여기서 **재검토 가능성이 닫혔다.** 이전 판정은 "지금은 없다"였고 데이터가 복구되면 다시 볼 여지를 남겨 뒀는데, 서비스 자체가 종료됐으므로 그 여지가 없다. `DATA_SOURCES.md` 6.10에서 두루누비 항목을 철회했다.

`brdDiv` 필터가 요청과 다른 구분을 돌려주는 문제(6.5의 1번)는 회신에서 다뤄지지 않았다. 서비스가 끝났다면 빈 결과나 오류를 주는 편이 맞지만, 매뉴얼 갱신으로 갈음하는 것으로 보인다. **다음 이용자도 같은 방식으로 오독할 수 있다는 뜻이다.**

### 그래서 유지되는 결정

`SCHEMA_CHANGE_ROUTE_GEOM.md`의 제안이 그대로 유효하다. 단 근거는 수정본을 따른다.

| # | 결정 | 근거 |
|---|---|---|
| 1 | `line_geom` → `GEOMETRY(MultiLineString, 4326)` | 한강종주는 반포(126.9986, 37.5110)에서 만나는 **Y자 분기**다. 단일 LineString으로 표현 불가 |
| 2 | 구간 분리 임계값 **3km** | 좌표 간격 중앙값 25m·p99.9 675m. 2.57km↔4.55km 사이가 비어 있다. 남한강 131.3 vs 공식 132 |
| 3 | `total_length_km` = **공식 안내값** | 계산값은 노선마다 담긴 범위가 달라 기준이 제각각이다(한강종주 0.49배·북한강 1.61배·동해안 경북 1.62배). 형상 길이는 `ST_Length`로 언제든 얻는다 |
