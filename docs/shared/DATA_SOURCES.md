### 2.2 자전거길 DB *(파일)*

| 항목 | 내용 |
|---|---|
| 제공기관 | 행정안전부 |
| 식별번호 | `3038533` |
| 형태 | ZIP (CSV 2 + XLSX 1) |
| 인증키 | 불필요 |
| 갱신 주기 | **수시 (1회성 데이터)** — 최종수정 2025-06-18 |
| 이용허락 | **이용허락범위 제한 없음** |

공식 설명이 **"국토종주 자전거길 13개"**로 명시한다. 코드북의 코드 14~46(강릉 경포호 산소길 등 지역 자전거길)은 부가 제공분이므로 `national_bike_route`는 **코드 1~13만 적재**한다.

**포함 파일**

| 파일 | 내용 | 규모 |
|---|---|---|
| `★국토종주 자전거길 노선좌표.csv` | 노선별 좌표 시퀀스 | 53,418행 / 노선 41개 |
| `★국토종주자전거길 주변시설 좌표정보.csv` | 인증센터·화장실·급수대·공기주입기 | 1,133행 |
| `★노선정보 코드북.xlsx` | 노선 코드 ↔ 노선명 매핑 | 41개 |

**검증 결과**

- 배포본 인코딩 **CP949**. 단 편집기에서 열어 저장하면 UTF-8로 바뀌므로
  **리더가 고정하지 않고 판별한다**(UTF-8 → MS949 순). 상세는 `BikeRouteCsvReader` 주석
- 시설 구분 4종 — 화장실 **688** / 급수대 185 / 인증센터 88 / **공기주입기 63** (중복 제거 후)
- 원본에 중복 109건. 적재 시 `(구분, 이름, 좌표)` 기준 제거 — 화장실 105 + 인증센터 4
- MVP 구간(한강 서울) 176건 — 화장실 97 / 급수대 75 / 인증센터 4. **공기주입기 0건**
  (그래서 AIR_PUMP는 서울시 API가 따로 필요하다 — 2.3 참조)
- 시설의 `이름` 컬럼이 **시설명이 아니라 노선명**이다 (급수대 75건이 전부 `"한강종주길"`)
- 노선명 표기가 코드북과 다르다 (`한강종주길` ↔ `한강종주자전거길`). 매핑 필요
- **두 CSV의 열 순서가 반대다.** 노선좌표는 3열=위도·4열=경도, 주변시설은 3열=경도·4열=위도
- 주변시설 CSV에는 **노선 코드가 없다.** FK는 좌표 기반(`ST_DWithin` 500m)으로 채운다

**적재 실측 (2026-08-12)**

| 대상 | 결과 |
|---|---|
| `national_bike_route` | 13노선 / 49,257점. 좌표 간격 3km 초과 시 파트 분리 → MultiLineString |
| `route_facility` | 1,133행 → **1,024건** (중복 109 제외) |
| 노선 연결 | **1,009건 (98.5%)**. 미연결 15건은 아래 6.1 참조 |

> ⚠️ 원본에 결함 5건이 있다. **6장에 정리했다** — 개선요청 현황과 함께 관리한다.

### 2.3 서울시 자전거 편의시설

| 항목 | 내용 |
|---|---|
| 제공기관 | 서울특별시 (디지털도시국 공간정보과) |
| 서비스명 | `tvBicycleEtc` |
| 엔드포인트 | `http://openapi.seoul.go.kr:8088/{KEY}/json/tvBicycleEtc/{시작}/{끝}/` |
| 인증키 | `SEOUL_OPEN_API_KEY` (서울 열린데이터광장) |
| 이용허락 | **공공누리 제1유형 — 출처표시 (상업적 이용·변경 가능)** ✅ |

**검증 결과 — 총 3,374건 (2026-08-12 적재 실측)**

- 좌표 결측 **0건**, `USE_YN` 전 건 "사용"
- **시설 종류를 구분하는 전용 필드가 없다.** `THMS_TYPE`·`THMS_NM`은 전 건 동일하다

#### 분류 규칙 (확정)

판정 로직은 `SeoulFacilityClassifier`에 있고 단위 테스트로 고정돼 있다.

| 판정 | 규칙 | 실측 | 적재 대상 |
|---|---|---|---|
| **AIR_PUMP** | 시설명에 **`주입기`** 포함 | **1,100** | `route_facility` |
| **REPAIR_SHOP** | `DTL_INFO_VL06`(운영형태) **또는** `VL07`(수리범위)이 채워짐 | **24** | `repair_shop` |
| OTHER | 그 외 (거치대·보관대) | 2,250 | **적재 안 함** |

**`주입기` 한 단어인 이유** — 변형이 전부 잡힌다. 오타(`자잔거`·`잦너거 공기주입기`),
공백 변형(`수동식 공기 주입기`), 방식 표기(태양광·자동식·기계식).
`공기주입`으로 잡으면 공백 변형을 놓쳐 1,098건이 된다.

**`VL08`을 쓰지 않는 이유** — 항목명은 "이동수리센터 순회일정"인데 값 7건 중 3건이
관리부서명이다. 08까지 넣으면 27건이 되고 `일반거치대` 2건이 수리센터로 잘못 분류된다.
상세는 6.1 참조.

**시설명으로 거르지 않는 이유** — `VL06`·`VL07`을 채웠다는 건 담당자가 "수리 기능이 있다"고
입력한 것이다. 시설명은 등록 당시 라벨일 뿐이고 거치대 옆 간이 수리대 사례도 있다.
이름으로 뒤집으면 우리 추측을 원본 입력 위에 두게 된다. 오탐 2건(6.1)을 감수한다.

**거치대·보관대를 적재하지 않는 이유** — `bike_parking` 소스는 행안부 자전거보관소 API로
확정돼 있다(2.6, 서울 2,698건). 함께 넣으면 중복 소스가 된다.

**주의**

- 1회 요청 최대 1,000건 (초과 시 `ERROR-336`)
- 인증키가 틀리면 json을 요청해도 **XML로 응답**한다
- https 미지원. `http` + 8088 포트 고정
- 1,000건 응답이 수 MB라 WebClient 기본 버퍼(256KB)로는 받을 수 없다
- **JSON 루트 키가 서비스명과 다를 수 있다** — 2.4·2.7 참조

**선정조건**: 반경 200m 내 자전거 사고 4건 이상 (사망사고 포함 시 3건)

**검증 결과**

- `geom_json`이 **GeoJSON Polygon 문자열**로 온다. `ST_GeomFromGeoJSON()`에 바로 넣을 수 있다
- 폴리곤은 33개 점의 반경 200m 원형 근사다
- 응답 구조가 TourAPI와 다르다. `response.header/body` 래핑이 없고 정상 코드가 `"00"`이다

- **데이터가 희소하다** — 강남구 4건. 자전거 사고다발지는 도심 교차로에 생기고 한강 자전거도로에는 거의 없다. 회피 기능의 실효가 제한적일 수 있다
- `guGun`이 필수로 보인다 (서울 25개 구 각각 호출 필요). *미확인*
- `searchYearCd` 동작 여부 *미확인*

### 2.6 자전거보관소정보 조회서비스

| 항목 | 내용 |
|---|---|
| 제공기관 | 행정안전부 (지역디지털협력과) |
| 식별번호 | `15155044` |
| 엔드포인트 | `https://apis.data.go.kr/1741000/bicycle_parking_info/info` |
| 인증키 | 공공데이터포털 키 |
| 갱신 | **매일** (2일 전 기준 현행화) |
| 이용허락 | **이용허락범위 제한 없음** |

**검증 결과 — 서울 2,698건**

- 좌표가 `WGS84_LAT`/`WGS84_LOT`로 온다
- `MNG_NO`가 고유 관리번호다 → `bike_parking.mgmt_no` UPSERT 키
- `cond[LCTN_ROAD_NM_ADDR::LIKE]`로 시도 단위 조회가 가능하다
- `numOfRows` 최대 100 → 서울만 27회 호출

> ⚠️ 명세 설명에 **"좌표계 : 보정계수 안들어간 Bessel 중부원점TM(EPSG:5174)"**라고 적혀 있으나 실제 값은 `37.594052 / 126.998777`로 **WGS84가 맞다.** `ST_Transform` 없이 적재한다.

- 자치구별 결측 편차가 크다. `INSTL_SHP`·`INSTL_YR`·`SNSHD_INSTL_YN`이 비어 있는 자치구가 있다. 실제로 쓰는 이름·주소·좌표·보관대수·관리기관은 채워져 있다

### 2.10 공간정보 오픈플랫폼 WMS/WFS *(미채택)*

| 항목 | 내용 |
|---|---|
| 제공기관 | 국토교통부 (V-World) |
| 엔드포인트 | `https://api.vworld.kr/req/wfs` |
| 레이어 | `lt_p_bycracks` (자전거보관소) |
| 인증키 | `V_WORLD_KEY` (도메인 등록 필요) |

2.6과 비교하기 위해 실호출했다. GeoJSON·WGS84로 응답하고 속성도 대응하지만 **고유 관리번호가 없어** UPSERT를 할 수 없다. 2.6을 채택했다.

### ⚠️ 이용약관 제약이 공공데이터포털과 다르다

V-World는 공공누리가 아니라 **자체 이용약관**을 적용한다. 제약이 훨씬 강하다.

> **제19조(저작권) ②** 회원은 서비스를 이용하여 얻는 정보를 **사전 승낙 없이 복사, 복제, 변경, 번역, 출판, 방송, 기타 등의 방법으로 사용하거나 이를 타인에게 제공할 수 없습니다.**

> **금지행위** — 운영기관의 동의 없이 **영리를 목적으로 서비스를 이용하는 행위**

우리가 하려던 건 WFS 응답을 **DB에 적재(복제)하고 가공해 서비스로 제공**하는 것이라 이 조항에 걸릴 소지가 있다. 반면 2.6(행안부)은 "이용허락범위 제한 없음"이다.

고유키 부재만으로도 미채택을 고려했고 **약관만 봐도 같은 결론이 나온다.** 재검토하게 되더라도 이 조항을 먼저 확인해야 한다.

**호출 시 주의** (재검토할 경우를 대비해 남긴다)

- `OUTPUT=application/json` → GeoJSON, `SRSNAME=EPSG:4326` → WGS84
- 기본 좌표계가 `EPSG:900913`(미터)이라 `SRSNAME` 명시가 필수다
- `EPSG:4326`일 때 BBOX 축 순서가 뒤집힌다 — `(ymin,xmin,ymax,xmax)`
- 서버 호출 시 `DOMAIN` 파라미터에 발급 시 등록한 도메인을 넣는다

**반경을 넓히지 않는다.** `/pois/nearby`는 좌표 반경 검색이라 FK를 쓰지 않으므로 미연결 시설도 지도에 정상 표시된다. 반대로 넓히면 남한강·북한강·한강종주가 팔당 부근에서

| 4 | **`VL01`(운영시간)에 위치·시설 설명.** `신림역 5번출구에서 직진방향`, `방치자전거 집하장(노원남부)` | 2+ | 가공 없이 그대로 저장 |

> 개선요청을 넣는다면 이 논지로 묶는 게 설득력이 있다.

**그 외** — 같은 주소에 두 건이 등록돼 있다.
`도림천자전거수리센터` / `자전거수리센터` 모두 `관악구 남부순환로 1583`.
이름이 달라 자연키로는 별개로 들어간다. 같은 시설의 중복 등록 가능성이 높다.

### 6.6 수리센터 오탐 2건 — 그대로 둔다

24건 중 2건이 수리센터가 아니다(6.5의 3번). 판정에서 빼지 않은 이유는 이렇다.

- 규칙을 "제공자 입력을 따른다"로 정했다. 이름으로 뒤집으면 원칙이 무너진다
- 둘 다 **노원구라 MVP 구간(한강)과 무관**하다
- 24건 중 2건이고, 피해는 "수리소로 표시됐는데 집하장" 수준이다

**검수 지표가 작동했다.** `hasRepairScope: false` 8건만 보면 됐고 그중 2건이 문제였다.
`true` 16건은 오탐 0건이다. 화면에 실제로 노출될 때 다시 판단한다.
